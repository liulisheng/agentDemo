### Worker 恢复与 UNKNOWN

- Docker Run Worker 重启后能处理新 Session Run；旧 Fake Session 引用不能跨进程恢复时按 `UNKNOWN`/`INTERRUPTED` 隔离。对隔离 Run 注入过期 ACTIVE Session lease 后，重启 Worker 会将 Run 收敛为 `UNKNOWN`、fencing token 递增、Session 变为 `INTERRUPTED`、lease 转为 `QUARANTINED`。
- Stdio timeout、owner task 取消和 lease loss 后清理 MCP 子进程的回归通过（`tests/test_mcp_stdio_host.py`）。
- Approval Worker 的远端 timeout/lease loss 单元用例验证 Run/Approval=`UNKNOWN` 且不重发；disposable MySQL 集成用例验证过期 RUNNING Approval lease 被回收为 UNKNOWN、fencing token 递增，并且随后 claim 不会再次执行该动作。
- 本次真实 DolphinScheduler 写入均收到明确成功响应；未在真实服务上注入“远端已执行但响应丢失”故障。该边界由上述 UNKNOWN 单元/MySQL 用例覆盖，真实生产故障演练仍待单独安排。
- 现有同步 `/api/v1/sessions/{id}/runs` API 在 Docker 本机运行成功，保持兼容；知识库未绑定、未接入。
