# 员工版本编辑与下线实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为员工版本和 Deployment 提供清晰的编辑、版本下线、部署下线/重新上线操作，并在后端阻止失效状态进入新请求。

**Architecture:** 复用现有 `DEPRECATED` 与 `DISABLED` 状态；服务层与 MySQL Repository 分别对版本和 Deployment 执行租户范围事务状态转换。版本下线与 Deployment 下线相互独立；版本下线后仍 ACTIVE 的历史 Deployment 可继续工作，直到管理员单独停用。前端员工时间线区分编辑 DRAFT、从 PUBLISHED/DEPRECATED fork 和下线版本，部署记录页管理 ACTIVE/DISABLED。

**Tech Stack:** Python 3.12、FastAPI、MySQL 8.4、React 19、TypeScript、Ant Design 5、React Router 7、TanStack Query 5。

**Spec:** `docs/superpowers/specs/2026-11-16-员工版本编辑与下线设计.md`

## Global Constraints

- 已发布与已下线员工版本保持不可变；需要编辑时创建新的 DRAFT。
- `DRAFT -> PUBLISHED -> DEPRECATED`；`DEPRECATED` 不可恢复，允许作为新 DRAFT 的 fork 来源。
- Deployment 状态为 `ACTIVE <-> DISABLED`；仅 ACTIVE Deployment 接受新 Session 与新 Run。
- 版本下线不自动停用任何 Deployment；界面展示仍 ACTIVE 的数量和前往部署记录的入口。
- 现有会话提交新 Run 时重新检查 Deployment 状态；已开始的 Runtime 执行不会被取消。
- 已存在 Run 的相同幂等键/摘要重放必须返回原 Run；不同摘要返回 `IDEMPOTENCY_CONFLICT`；仅未命中的新 Run 受 Deployment ACTIVE 准入检查限制。
- 所有写 API 进行管理员、platform_id 和 tenant_id 校验；租户越权沿用 404 语义。
- 不新增数据库表、字段、索引或 migration；状态转换和审计记录在 MySQL 事务内提交。
- 代码注释、公共类/函数说明、产品文案和设计文档使用中文。
- 不在本计划中重排或提交工作区里既有的其他改动。

- 项目明确要求 commit message 和 commit body 使用中文；每个实现提交 body 包含“变更内容 / 影响范围 / 验证结果 / 风险和后续”。
- 如需新增或运行自动化测试，先取得用户对测试与验证的明确授权；未获授权时按本计划执行编译、构建、文档与差异校验，并如实记录未验证行为。
