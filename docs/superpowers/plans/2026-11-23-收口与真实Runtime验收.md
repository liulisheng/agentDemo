# 当前实现收口与真实 Runtime 验收计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将当前工作区中的运行配置、ModelRoute 生命周期和 DeepSeek Harness 默认引擎变更拆分、复验、归档并提交，然后进入真实 Runtime 与生产边界验收。

**架构：** 先按 OpenSpec 变更边界整理已有代码和文档，再执行后端、前端、Harness、迁移和 Compose 的验证门禁。收口完成后，单独推进真实模型服务、生产身份/凭据和跨进程恢复，不在当前提交中扩大功能范围。

**技术栈：** FastAPI、MySQL 8.4、React/Vite、DeepSeek Harness SDK、Docker Compose、OpenSpec。

**规格依据：** `openspec/changes/deepseek-harness-default-runtime/`、`openspec/changes/archive/2026-11-22-workbench-runtime-configuration-options/`、`openspec/changes/archive/2026-11-23-workbench-runtime-ui-and-model-route-management/`。

## 全局约束

- Commit message、commit body、公共注释和交付文档使用中文。
- 不提交 `.env`、`.agents/`、缓存、备份、凭据或本机 OpenSpec/REA 配置。
- API 和 Worker 必须读取同一个 `AGENT_PLATFORM_RUNTIME_ENGINE`，SecretRef 只在 Worker 出站前解析。
- 已创建的 Session/Run 继续使用不可变快照；ModelRoute 撤销、版本冲突和跨租户访问必须 fail closed。
- 真实供应商调用、生产身份、生产 Secret Manager 和跨进程恢复在具备环境前只能标记为未验证。

## 审查重点

- 运行引擎默认值是否在 API、Run Worker 和验收 Compose 中一致。
- `deepseek` 历史别名是否只做解析兼容，Provider 清单是否只展示 `deepseek_harness`。
- SecretRef、endpoint、命令行参数和 MCP 凭据是否没有进入 API 响应、Profile、Trace 或 RunSnapshot。
- V009/既有 migration 的中文 COMMENT、租户键、回填和回滚边界是否保持一致。
- ModelRoute `REVOKED`、Deployment fallback、旧快照读取和并发绑定是否仍然满足规格。
