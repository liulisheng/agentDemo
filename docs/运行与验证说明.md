# 运行与验证说明

完整的 MySQL、LocalObjectStore、Fake Runtime 部署和恢复说明见 [`本地控制面闭环与运维`](本地控制面闭环与运维.md)。

## 明确选择 Fake 模式

Fake 模式供测试/离线演示使用，不证明 MySQL/对象持久化：

```bash
cd backend
AGENT_PLATFORM_MODE=fake python -m uvicorn agent_platform.main:app --host 127.0.0.1 --port 8000
```

## 明确选择 MySQL 模式

API 启动前须创建 MySQL 数据库，显式运行 migration 和 Fake identity seed，再设置配置：

```bash
agent-platform-migration preflight --migrations-dir docs/migrations
agent-platform-migration apply --migrations-dir docs/migrations
agent-platform-seed-fake-identity

export AGENT_PLATFORM_MODE=mysql
export AGENT_PLATFORM_IDENTITY_PROVIDER=fake
export AGENT_PLATFORM_DATA_ROOT="$HOME/.local/share/agent-platform"
cd backend
python -m uvicorn agent_platform.main:app --host 127.0.0.1 --port 8000
```

缺失 MySQL 配置或连接失败时服务启动失败，不会回落到内存。迁移只在显式 `agent-platform-migration apply` 命令中执行；API 启动只读预检，不会创建平台、租户或用户。

## 前端

```bash
cd frontend
npm run dev -- --host 127.0.0.1
```

如果 `5173` 已被占用，Vite 会自动选择下一个本地端口。

## 验证命令

```bash
cd backend
python -m pytest tests -q
python -m ruff check src tests
python -m compileall -q src

cd ../frontend
npm test
npm run build
```

只读 API 冒烟：

```bash
curl http://127.0.0.1:8000/api/health
curl -H 'X-Fake-User: admin-local' \
  http://127.0.0.1:8000/api/v1/digital-employees
```

这里的 `X-Fake-User` 仅适用于显式 Fake identity 本地模式。真实身份提供方未在本 Change 中接入。
