# 数字员工最小闭环

更新时间：2026-11-14
状态：本地 Fake Runtime 闭环已实现，生产持久化与真实 Runtime 未接入

## 架构图

~~~mermaid
flowchart LR
  C[FastAPI 路由] --> A[ControlPlaneService]
  A --> D[CatalogService]
  A --> R[RuntimeAdapter]
  A --> T[Trace 内存仓储]
  A --> I[Fake IdentityContext]
  R --> F[FakeRuntimeAdapter]
  F --> O[opaque Runtime 引用]
~~~

控制面保存数字员工、Skill、Tool、Deployment、Session、Run 的业务快照；Fake Runtime 只负责生命周期、确定性输出和标准事件。Runtime 私有 Session、结果以 opaque 引用进入 Trace，不解析 Harness 内部状态。

## 数据模型

~~~mermaid
erDiagram
  DIGITAL_EMPLOYEE ||--o{ DIGITAL_EMPLOYEE_VERSION : has
  DIGITAL_EMPLOYEE_VERSION ||--o{ SKILL_VERSION : binds
  DIGITAL_EMPLOYEE_VERSION ||--o{ TOOL_VERSION : allows
  DIGITAL_EMPLOYEE_VERSION ||--|| DEPLOYMENT : pinned_by
  DEPLOYMENT ||--o{ SESSION : opens
  SESSION ||--o{ RUN : contains
  RUN ||--o{ TRACE_SPAN : emits
  RUN ||--|| USAGE_RECORD : records
~~~

关键快照字段：

| 对象 | 字段 | 说明 |
|---|---|---|
| DigitalEmployeeVersion | employee_id、version、skill_ids、tool_ids、execution_profile_id | 发布后冻结 |
| Deployment | deployment_id、tenant_id、employee_version | 新 Run 解析的唯一入口 |
| RunSnapshot | employee_version、Skill/Tool IDs、Profile ID | Run 开始时复制，发布新版本不影响 |
| RuntimeReference | engine_name、runtime_session_ref、runtime_result_ref | Runtime 私有状态的审计引用 |
| TraceSpan | trace_id、parent_span_id、span_type、status、attributes | 只保留元数据和摘要 |

## 发布和执行流程

~~~mermaid
sequenceDiagram
  participant U as 管理端
  participant API as FastAPI
  participant CAT as CatalogService
  participant CP as ControlPlaneService
  participant F as FakeRuntimeAdapter
  participant TR as Trace

  U->>API: 创建并发布 Tool
  API->>CAT: 校验租户并保存 PUBLISHED Tool
  U->>API: 创建并发布 Skill
  API->>CAT: 校验 Tool 依赖
  U->>API: 创建员工版本并发布
  API->>CAT: 校验 Skill/Tool/Profile 依赖
  U->>API: 创建 Deployment
  API->>CAT: 固定已发布员工版本
  U->>API: 创建 Session
  API->>CP: 创建 Session Span 和 trace_id
  U->>API: 创建 Run
  API->>CP: 复制版本快照并解析 Skill/Tool 交集
  CP->>F: create/resume + run
  F-->>CP: RuntimeEvent、Usage、opaque refs
  CP->>TR: 保存 Session/Run/Skill/Tool/Runtime/Model/Result Span
  API-->>U: Run 结果
  U->>API: GET /runs/{id}/trace
  API-->>U: 有序时间线和用量
~~~

## 状态

~~~mermaid
stateDiagram-v2
  [*] --> DRAFT
  DRAFT --> PUBLISHED: 依赖校验通过
  PUBLISHED --> DEPRECATED: 废弃
  PUBLISHED --> ACTIVE: 创建 Deployment
  ACTIVE --> RUNNING: 创建 Run
  RUNNING --> SUCCEEDED: Fake Runtime 完成
  RUNNING --> FAILED: 工具策略或 Runtime 错误
~~~

## HTTP 接口

所有接口使用 /api/v1 前缀和 X-Fake-User 身份头：

- POST /tools、POST /tools/{id}/publish
- POST /skills、POST /skills/{id}/publish
- POST /digital-employees
- POST /digital-employees/{id}/versions
- POST /digital-employees/{id}/versions/{version}/publish
- POST /deployments、GET /deployments
- POST /sessions
- POST /sessions/{id}/runs
- GET /runs/{id}、GET /runs/{id}/trace
- GET /sessions/{id}/trace

错误响应统一为 code、message、request_id、details。跨租户资源返回 404 RESOURCE_NOT_FOUND，幂等键内容变化返回 409 IDEMPOTENCY_CONFLICT。

## 未验证项与边界

- 当前仓储是进程内内存实现，重启后目录、Session、Run 和 Trace 不保留。
- 未接入 MySQL、真实 DeepSeek/Codex、生产 Worker、沙箱和对象存储。
- Fake Runtime 不模拟供应商私有上下文压缩、审批和流式事件。
- harness-engine 与 backend 通过平台 RuntimeAdapter 边界保持独立，后续可增加真实适配器。
