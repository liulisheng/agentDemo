# 员工工作台界面改造计划

**目标：** 将数字员工详情改成清晰、宽松的工作台；每种资源类型独立分区，避免把 Skill、Tool 和其他资源混在一个表单或列表中。

**架构：** 保留“数字员工 / 资源中心 / 部署记录”一级导航。员工详情作为聚合页，分为概览、每种已启用资源类型的独立 Tab、版本与发布；编辑器按任务分区。继续使用精确员工版本绑定和当前 API，不改变运行时快照语义。

**技术栈：** React、TypeScript、React Router、TanStack Query、Ant Design、Vitest。

**设计依据：** 用户已确认的“员工工作台 + 能力与资源分区”方案，以及“不同类型资源不得放在同一个表单列表、界面留白充足、交互保持简单”的补充要求。

## 全局约束

- 当前员工资源页分别呈现 Skills、Tools Tab；知识库按已确认的低优先级继续延后。
- 每种资源类型使用独立页签、状态、数量和操作入口；未来类型新增独立页签。
- 员工版本绑定资源的 ID、精确版本、来源模式和只读规则保持不变。
- 页面文案和代码注释使用中文；不改变 SQL Schema 或 API 契约。

## 任务 2：重做员工详情为宽松工作台

**文件：**
- 修改：`frontend/src/features/digital-employees/EmployeeDetailPage.tsx`
- 修改：`frontend/src/styles.css`
- 测试：`frontend/src/features/digital-employees/EmployeeManagementPages.test.tsx`

**实现：**

1. 保留顶部员工名称、类型、状态和描述，编辑/归档操作移入简短操作区。
2. 使用“概览 / Skills / Tools / 版本与发布”页签：
   - **概览**：单张员工信息卡和轻量版本摘要，不放跨页跳转按钮。
   - **Skills**：当前员工版本绑定的 Skill 清单、文件工作区入口和独立添加操作。
   - **Tools**：当前员工版本绑定的 Tool 清单、Tool 目录入口和独立绑定操作。
   - **版本与发布**：宽松的版本卡片时间线；DRAFT 提供“继续配置”，PUBLISHED 只读。
3. Skills 与 Tools 页各自提供员工版本选择器；切换后只显示对应类型的精确版本绑定。
4. 新类型启用时新增自己的 Tab，不并入既有类型列表。
5. 对长名称、空依赖、加载、错误和成员只读状态添加组件测试。

4. 顶部固定“保存草稿 / 测试 / 发布”操作，窄屏时按钮换行，不要求横向滚动。
5. 保留脏状态提示、发布预检和 Fake Runtime 测试行为，并由组件测试验证。

## 任务 5：按业务功能拆分 FastAPI 路由

**文件：**
- 修改：`backend/src/agent_platform/api/routes.py`，收敛为路由组聚合器。
- 新建：`backend/src/agent_platform/api/route_modules/common.py`，放置身份依赖别名和租户一致性检查。
- 新建：`backend/src/agent_platform/api/route_modules/serializers.py`，放置共享 JSON 响应序列化器。
- 新建：`backend/src/agent_platform/api/route_modules/catalog.py`，放置员工、Skill、Tool、ExecutionProfile 和 ModelRoute 路由。
- 新建：`backend/src/agent_platform/api/route_modules/deployments.py`，放置 Deployment、审计、Session、Run、Trace 路由。
- 新建：`backend/src/agent_platform/api/route_modules/resource_center.py`，放置 Hub 发布、目录、Grant 和导入路由。
- 新建：`backend/src/agent_platform/api/route_modules/skill_files.py`，放置 Skill 文件、ZIP preview/commit 路由。
- 新建：`backend/src/agent_platform/api/route_modules/conversations.py`，放置 Conversation 与消息路由。

**接口边界：** 各业务模块独立创建 `APIRouter()`；聚合器继续导出带 `/api/v1` 前缀的 `router`，供 `app.py` 挂载。迁移中不改变 URL、HTTP method、响应 Schema、身份 Header 或 Service 调用语义。

**步骤：**

1. 按 endpoint 名称把当前路由映射到六个业务组，确认每条路径只出现一次。
2. 先用 AST 从原模块提取响应序列化器和依赖别名，形成共享 `serializers.py` / `common.py`。
3. 按组迁移 handler，业务模块只导入自身需要的 Schema、Service、领域类型和共享 helper。
4. 把旧 `routes.py` 改为只 include 六个子 router；`from agent_platform.api.routes import router` 保持兼容。
5. 跑 FastAPI OpenAPI 路径清单、完整后端 MySQL 集成与离线测试、Ruff 和 `compileall`，确认路径、method 和 behavior 不变。
6. 更新中文 API 文档及本计划的已验证记录。
