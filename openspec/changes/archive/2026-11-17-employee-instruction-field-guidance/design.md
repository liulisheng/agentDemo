# Design

## Context

动机和行为要求见 `proposal.md` 与 `specs/employee-field-guidance/spec.md`。当前员工描述字段出现在员工目录创建弹窗和员工详情编辑弹窗；系统指令出现在员工详情的新建版本弹窗和版本编辑器；Skill 初始指令出现在员工上下文的 Skill 创建页和资源中心创建抽屉。运行解析使用员工版本的 `system_prompt`，并把已绑定 Skill 的指令内容加入运行请求；员工描述仅作为目录资料展示。

## Goals / Non-Goals

**Goals:**

- 在每个现有入口的目标字段附近展示一致、常驻的用途说明。
- 保持说明与表单值分离，避免帮助文案进入 API 请求或持久化字段。
- 用前端验收覆盖字段说明在所有创建和编辑入口中的可见性。

**Non-Goals:**

- 不改变员工、员工版本或 Skill 版本的数据结构、API、保存校验和运行解析。
- 不调整 `digital-employee-resource-center` 的任务或验收状态。
- 不重构员工、版本或 Skill 表单布局。

## Decisions

### 在字段控件下方展示常驻辅助说明

使用现有 Ant Design `Form.Item` 的辅助说明区域展示文案，使其始终可见并与字段绑定。相比 placeholder，辅助说明在管理员开始填写后仍然保留；相比 Tooltip，不要求悬停或额外点击。文案沿用 proposal 和 spec 中的中文句子，在对应字段的所有创建/编辑入口保持一致。

### 只扩展前端呈现和交互验收

说明作为表单静态呈现内容，不加入表单值、API payload 或 RuntimeRequest。员工描述说明其目录范围；员工版本说明每次运行都使用；Skill 说明仅在员工版本绑定该 Skill 时应用。前端测试检查各表单字段与说明同时可见，并保留现有提交流程断言。

### 按项目文档约定补充中文说明文档

新增一份简短的 `docs/员工字段用途与填写说明.md`，记录组件关系图、填写流程图、相关数据字段、API/运行状态边界、验证状态与验证命令。该文档用于解释此次 UI 行为，不引入新的 API 或数据模型契约。

## Risks / Trade-offs

- 文案在多个入口重复呈现时可能发生漂移 → 在各入口的前端测试中断言对应说明，并将统一文案记录在本 Change 的规格和中文文档中。
- Skill 文案可能被理解成绑定任意版本都会应用 → 明确指向绑定此 Skill 的员工版本，并在中文文档中说明员工版本固定 Skill 精确版本。

## Migration Plan

无需数据库或 API 迁移。随前端版本发布即可；若需回退，移除新增辅助说明和对应验收断言，不影响已保存数据或既有运行。
