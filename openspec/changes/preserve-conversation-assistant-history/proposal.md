# Proposal

## 目标

修复员工工作台同一 Session 连续提交多轮问答时，第二轮加载后第一轮助手回答从时间线消失的问题。所有已完成的用户消息和助手回答必须按会话顺序可恢复。

## 范围

- 将助手最终答复作为 Conversation 的可恢复消息读取，不再只依赖当前最新 Run 的临时结果。
- 保留现有用户消息、Run、Trace、Approval 和租户授权边界。
- 增加两轮以上问答的前端回归测试、后端消息持久化/读取测试和中文验证文档。
- 提供静态 HTML 原型，覆盖正常、加载、空、错误和权限状态。

## 明确不做

- 不改变 Harness Session 的供应商历史格式或 Prompt 拼接规则。
- 不增加新的消息表；复用现有 `messages` 表的 `ASSISTANT` 记录和对象存储正文。
- 不改变 Run 状态机、审批授权、幂等键或跨租户访问策略。
- 不把模型正文写入 MySQL 明文字段。

## 影响面

后端 Run 完成路径、Conversation 消息查询、前端工作台时间线、相关测试和中文设计文档。

## 验收目标

同一 Session 完成第一轮和第二轮问答后，时间线同时显示两轮用户消息和两轮助手回答；刷新或重新打开 Conversation 后仍能恢复；无权租户不能读取正文；失败/未知 Run 不伪造成功助手回答。
